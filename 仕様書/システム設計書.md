# システム設計書 (Time Alert)

## 1. 基本アーキテクチャ
Manifest V3 (MV3) に準拠したChrome拡張機能として実装する。

- **技術選定:** 軽量化と高速動作を重視し、ReactやVueなどのフロントエンドフレームワークは**使用しない**。**Vanilla JS (標準JavaScript)** と標準のDOM APIを用いて状態管理とUIレンダリングを行う。ドラッグ＆ドロップ機能についても、SortableJS等の軽量ライブラリの利用、またはHTML5 Drag and Drop APIを直接実装する。
- **Side Panel (`sidepanel.html`, `sidepanel.js`, `sidepanel.css`等):** メインUI。視認性向上と保守性のため、JavaScriptはESモジュールを利用して機能ごとに分割（`sidepanel.js`, `utils.js`, `state.js`, `components.js`）している。カードの動的生成、折りたたみUIの制御、入力補完ロジック、タブ切り替え機能を提供する。
- **Background Service Worker (`background.js`):** アラームのスケジュール管理、通知の発火、Chromeタブの状態監視（アクティブか非アクティブか）、データ同期のコアロジックを担う。
- **Content Scripts (`content.js`, `content.css`):** アクティブなタブが存在する場合に、Webページ上にDOMを挿入して独自のポップアップ通知UI（画面上部からのスライドイン）を表示するために使用する。
- **設定ページ (Options Page):** 個別のポップアップではなく、専用の `settings/settings.html` を `manifest.json` の `options_page` として登録し、別タブで開くアーキテクチャを採用する。設定項目は `chrome.storage.sync` を介して保存され、サイドパネル側は `chrome.storage.onChanged` イベントを監視することで、リアルタイムに設定変更（テーマ、言語、音量など）をUIに反映する。
- **多言語対応 (i18n):** 独自のロジック、または Chrome標準の `chrome.i18n` API を利用して、日本語と英語のUIテキストの切り替えを実装する。

## 2. 時間・スケジュール管理
Service Workerはサスペンド（休止状態）になるため、`setTimeout` や `setInterval` による長時間のタイマー管理は機能しない。

- **`chrome.alarms` APIの活用:**
  タイマー・アラームともに、目標到達日時を計算し `chrome.alarms.create` を用いてシステムにスケジュールを登録する。
- **状態の復元:**
  サイドパネルが開かれた際は、ストレージに保存されている「開始時刻」と「設定時間」から現在時刻との差分を計算し、カウントダウン表示を正確に復元する。

## 3. ハイブリッド通知システムの実装ロジック
`chrome.alarms.onAlarm` イベントをService Workerで検知した際、以下のフローで処理を分岐させる。

1.  `chrome.tabs.query({ active: true, currentWindow: true })` を使用し、現在ユーザーが見ているアクティブなタブを取得する。
2.  **アクティブなタブが存在する場合:**
    対象タブのURLがContent Script実行可能なURL（`chrome://`, `chrome-extension://`, `chrome-error://`, `about:` 等でないもの）であるかを検証し、`chrome.tabs.sendMessage` を送信。Content Scriptがメッセージを受け取り、画面上部にカスタム通知UI（HTML要素）をスライドイン描画する。
3.  **アクティブなタブが存在しない（ブラウザ最小化中等）、Content Script が実行不可能なタブ（特殊ページ・オフラインエラー画面等）、またはタブ初期化中の場合:**
    `chrome.notifications.create` を使用して、OSのシステム通知を表示する（正規アイコン `icons/icon.png` を使用）。
    - **永続的鳴動状態からのUI復帰（トースト復元機能）:** Service Workerの終了（サスペンド）による状態喪失を防ぐため、保留通知は揮発性メモリではなく `chrome.storage.local` の `ringingItems` に基づいて一元管理される。ユーザーがブラウザを再度アクティブにした場合（ウィンドウフォーカスやタブ切り替え時）、または**タブの読み込みが完了した際（`chrome.tabs.onUpdated`）**に、`ringingItems` の内容を読み出し、現在のアクティブタブ上に拡張機能の独自ポップアップ通知（トースト）を自動描画する。描画成功時はOS通知をクリアして二重通知を防止する。
4.  **ツールバーアイコンバッジ通知:**
    通知発火と同時に、Chromeツールバーの拡張機能アイコン上にオレンジ色（`#ff8c00`）のバッジ「!」を表示し、ツールチップで鳴動中であることを表示する。これにより、Web画面内にトーストが表示できないオフライン環境や起動時でも、視覚的に即座に鳴動を把握・停止可能とする。

## 4. データストレージ戦略
- **`chrome.storage.sync`**:
  カードのリスト（順序含む）、タイトル、時間設定、曜日設定、トグル状態などの軽量なJSONデータを保存。これにより複数端末間での同期を実現する。
- **`IndexedDB` (または `chrome.storage.local`)**:
  ユーザーがアップロードしたカスタム音声ファイルの実データ（BlobやBase64）を保存する。同期の容量制限（1アイテム8KB、全体100KB）を回避するため、これらは端末ローカルに留める。また、端末ローカルで現在鳴動中のアイテム一覧（`ringingItems`）を一時状態として保存し、Service Worker・サイドパネル・Content Script間のリアルタイム同期に利用する。
- **データのエクスポート・インポート**:
  `chrome.storage.sync` 内のデータを JSON ファイル（`.json`）として外部にエクスポート、または外部ファイルからインポートする機能を提供。エクスポートは「タイマーのみ」「アラームのみ」「両方（すべて）」から対象を選択可能。インポート時は「既存データを削除して上書き（既存のアラームを全クリアしてインポートされたデータを再スケジュール）」か、「既存データに追加（追加するアイテムのIDを新しく生成し、既存のアラームを維持したまま追加スケジュール）」かを選択可能とする。

## 5. 音声再生の仕組み
- MV3のService Worker内では DOMの `Audio` オブジェクトが使用できない。
- **解決策:**
  - Content Scriptによるポップアップ通知が表示される場合は、Content Script側で音声を再生する。
  - システム通知（`chrome.notifications`）の場合は、**Offscreen Document API** (`chrome.offscreen.createDocument`) を一時的に生成し、その非表示ドキュメント内で音声を再生する手法を採用する。

## 6. 鳴動状態（Ringing State）の管理と連動停止
アラームおよびタイマー作動時の鳴動状態は、端末ローカルで一元管理される。

- **状態の保持 (`ringingItems`):**
  - アラーム発火時（`chrome.alarms.onAlarm`）、Service Workerが対象アイテムの情報（`id`, `type`, `title`, `triggeredAt`）を `chrome.storage.local` の `ringingItems` 配列に追加。
- **サイドパネルへの即時反映:**
  - サイドパネルは `chrome.storage.onChanged`（`namespace === 'local'`）を監視し、`ringingItems` の変動に応じて「アクティブアイテムヘッダー」と「カードリスト」の間に鳴動中カードをリアルタイム描画／消去する。
  - 現在表示中のタブ（タイマー／アラーム）に関係なく、鳴動中のアイテム（複数時は最新の1件を表示し「ほか〇〇件」と件数バッジを付与）がカードとして常時表示される。停止ボタン押下で鳴動中の全アイテムが一括停止される。
- **ツールバーアイコン（Actionバッジ）との連携:**
  - アラーム発火時および停止時に `updateActionBadge` が実行され、`ringingItems` の件数が1件以上の場合はアクセントカラー（オレンジ）のバッジ「!」と専用タイトルを拡張機能アイコンに設定。0件になった時点でバッジテキストを空文字にして消去する。
  - ブラウザ起動時（`chrome.runtime.onStartup`）にもバッジ状態を再評価・復元し、サイドパネルのアクションクリック動作（`chrome.sidePanel.setPanelBehavior`）を確実に設定する。
- **全方位連動停止 (`handleStopAlarm`):**
  - ユーザーが「サイドパネルの停止ボタン」「Webページのトースト通知」「OSのシステム通知」のいずれから停止操作を行っても、Service Workerの停止処理が実行される。
  - 対象アイテムが `ringingItems` から削除され、アイコンバッジが更新される。全アイテムが停止した場合は Offscreen Document への音声停止（`stopAudio`）および全タブへの通知消去メッセージ（`closeNotification`）が送信され、すべてのUI状態が整合して停止する。
