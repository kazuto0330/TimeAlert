# システム設計書 (Time Alert)

## 1. 基本アーキテクチャ
Manifest V3 (MV3) に準拠したChrome拡張機能として実装する。

- **技術選定:** 軽量化と高速動作を重視し、ReactやVueなどのフロントエンドフレームワークは**使用しない**。**Vanilla JS (標準JavaScript)** と標準のDOM APIを用いて状態管理とUIレンダリングを行う。ドラッグ＆ドロップ機能についても、SortableJS等の軽量ライブラリの利用、またはHTML5 Drag and Drop APIを直接実装する。
- **Side Panel (`side_panel.html`, `side_panel.js`, `style.css`等):** メインUI。カードの動的生成、折りたたみUIの制御、入力補完ロジック、タブ切り替え機能を提供する。
- **Background Service Worker (`background.js`):** アラームのスケジュール管理、通知の発火、Chromeタブの状態監視（アクティブか非アクティブか）、データ同期のコアロジックを担う。
- **Content Scripts (`content.js`, `content.css`):** アクティブなタブが存在する場合に、Webページ上にDOMを挿入して独自のポップアップ通知UI（画面上部からのスライドイン）を表示するために使用する。
- **Options (`options.html` またはサイドパネル内の設定領域):** カスタム音声のアップロードや全体的な音量設定を管理する。

## 2. 時間・スケジュール管理
Service Workerはサスペンド（休止状態）になるため、`setTimeout` や `setInterval` による長時間のタイマー管理は機能しない。

- **`chrome.alarms` APIの活用:**
  タイマー・アラームともに、目標到達日時を計算し `chrome.alarms.create` を用いてシステムにスケジュールを登録する。
- **状態の復元:**
  サイドパネルが開かれた際は、ストレージに保存されている「開始時刻」と「設定時間」から現在時刻との差分を計算し、カウントダウン表示を正確に復元する。

## 3. ハイブリッド通知システムの実装ロジック
`chrome.alarms.onAlarm` イベントをService Workerで検知した際、以下のフローで処理を分岐させる。

1.  `chrome.tabs.query({ active: true, currentWindow: true })` を使用し、現在ユーザーが見ているアクティブなタブを取得する。
2.  **アクティブなタブが存在する場合:**
    そのタブに対して `chrome.tabs.sendMessage` を送信。Content Scriptがメッセージを受け取り、画面上部にカスタム通知UI（HTML要素）をスライドイン描画する。
3.  **アクティブなタブが存在しない（ブラウザ最小化中等）、または Content Script が実行不可能なタブ（`chrome://` など）の場合:**
    `chrome.notifications.create` を使用して、OSのシステム通知を表示する。

## 4. データストレージ戦略
- **`chrome.storage.sync`**:
  カードのリスト（順序含む）、タイトル、時間設定、曜日設定、トグル状態などの軽量なJSONデータを保存。これにより複数端末間での同期を実現する。
- **`IndexedDB` (または `chrome.storage.local`)**:
  ユーザーがアップロードしたカスタム音声ファイルの実データ（BlobやBase64）を保存する。同期の容量制限（1アイテム8KB、全体100KB）を回避するため、これらは端末ローカルに留める。

## 5. 音声再生の仕組み
- MV3のService Worker内では DOMの `Audio` オブジェクトが使用できない。
- **解決策:**
  - Content Scriptによるポップアップ通知が表示される場合は、Content Script側で音声を再生する。
  - システム通知（`chrome.notifications`）の場合は、**Offscreen Document API** (`chrome.offscreen.createDocument`) を一時的に生成し、その非表示ドキュメント内で音声を再生する手法を採用する。
